# 10 AIへの引き継ぎプロンプト例

## 1. 実装計画を立てるAI向け

```
添付のZIPは、Three.jsで3Dのキャラと背景をリアルタイムに「現代的でリッチなドット絵」として描画する技術検証プロジェクトの引き継ぎ資料です。最終目標は、この技術を土台にしたJRPG作成ツールです。

00_README.md から順に読み、特に 06_設計原則と制約.md の不変条件を必ず守る前提で、05_ロードマップv6-v9.md の v6 の実装計画を立ててください。

計画には次を含めてください。
- リポジトリ構成(07を参考に、採用理由も)
- v5相当の移植をマイルストーン0とし、同等性の確認方法
- v6の小項目ごとの作業分割(Issue単位)、依存関係、受け入れ条件、実機での確認手順
- リスクと、依頼者に判断を求める点

09_依頼者への質問状.md の回答が添付されていない場合は、各項目の「未回答時の仮定」で進め、その仮定を計画中に明記してください。
```

## 2. 実装を担当するAI向け(Issueごと)

```
このリポジトリは、Three.jsで3D表現を低解像度でレンダリングし、整数倍に拡大してドット絵として表示するブラウザゲームの描画基盤です。docs/ の資料、特に 06_設計原則と制約.md を読み、その不変条件を壊さないでください。

【タスク】(Issueの内容を貼り付け)

【守ること】
- カメラ・キャラ・模様はすべて整数ピクセル座標を基準にし、画素中心(+0.5)で判定する
- ロジックは60Hz固定ティック
- シェーダーに角度の固定値を埋め込まず、カメラ基底のユニフォームを使う
- 深度は1つのバッファで扱い、物体ごとの深度ルールで前後関係を決める

【完了条件】
- 受け入れ条件を満たすこと
- ちらつき検査(静止物の画素が、カメラの移動量ぶん平行移動するだけであること)に合格すること
- 変更点・確認手順・スクリーンショットをPRに記載すること
```
