# 07 推奨リポジトリ構成と開発フロー

あくまで推奨案。採用する構成は実装計画の段階で決める(09 の質問状で依頼者の希望を確認)。

## 1. ディレクトリ構成案

```
/
├─ index.html
├─ package.json            # 例:Vite + three(npm)
├─ src/
│  ├─ main.ts|js           # 起動・メインループ(60Hz固定ティック+描画)
│  ├─ core/
│  │  ├─ pixelGrid.*       # 論理解像度、整数倍表示、ピクセル原点、カメラのスナップ
│  │  ├─ cameraBasis.*     # カメラ基底(右・上・手前)の管理
│  │  └─ time.*            # 固定ティック、時間の固定(検証用)
│  ├─ render/
│  │  ├─ gbuffer.*         # G-buffer(v6)
│  │  ├─ lighting.*        # 太陽・点・スポット・面光源、影
│  │  ├─ post/             # 輪郭線、ブルーム、AO、合成
│  │  ├─ depthRules.*      # 3D/手前の板/奥の板/地面
│  │  └─ shaders/          # GLSL(部品ごとにファイル分割)
│  ├─ materials/           # 色ランプ、模様(平面・曲面)、地面、素材生成
│  ├─ world/
│  │  ├─ terrain/          # 頂点型マップ、マーチングスクエア、SDF、スプライン
│  │  ├─ props/            # 建物・小物の生成関数
│  │  ├─ vegetation/       # 樹木・草(v7, v9)
│  │  └─ water/            # v8
│  ├─ fx/
│  │  ├─ particles/
│  │  └─ decals/           # 手描きドット絵の描き込み層
│  ├─ character/
│  │  ├─ rig.*             # 現在はプリミティブ人形
│  │  ├─ face.*            # ドット顔、表情、眉
│  │  └─ emotes.*          # 感情表現(アイコン+モーション)
│  ├─ gameplay/
│  │  ├─ movement.*        # 8方向ピクセル移動、向きのヒステリシス
│  │  └─ collision.*       # 楕円当たり判定、SDF
│  ├─ data/                # マップ・スプライト(ドット絵文字列)・プリセット
│  └─ debug/               # バッファ表示、段階比較、焼き出し、HUD
└─ docs/                   # 本資料一式
```

## 2. Three.js について

- プロトタイプは r128(cdnjs)。新規構成では npm で最新版を使うのが自然だが、移行時は公式の移行ガイドで以下を確認すること:出力の色空間とカラーマネジメントの既定値、複数レンダーターゲットのAPI、深度テクスチャ、ShaderMaterial のGLSL変換の挙動。
- まずは「r128版と同じ見た目になること」を確認してから機能追加に入る。
- 独自シェーダーが中心なので、ShaderMaterial(または RawShaderMaterial)ベースで進める。

## 3. 開発フロー案(GitHub)

1. v5相当の移植をマイルストーン0とし、スクリーンショット比較で同等性を確認。
2. ロードマップの各項目を Issue 化し、1 Issue = 1 PR を基本とする。
3. 各PRに「受け入れ条件」「確認手順」「実機確認の要否」を書く。
4. 依頼者がスマホ実機でfpsと見た目を確認し、フィードバックを Issue に戻す。

## 4. 検証のための仕組み(推奨)

- **時間の固定**:葉の揺れ・水・ディザ・パーティクルを含めて特定の時刻で止められるようにする(見た目の差分比較のため)。
- **固定カメラ位置のスクリーンショット**:いくつかの定位置で自動撮影し、PR前後で比較する(視覚的な回帰テスト)。
- **バッファ表示**:色・法線・深度・ID・照明・影・AOを個別に表示できるデバッグビュー。
- **ちらつき検査**:キャラを一定速度で横・縦・斜めに動かし、連続フレームで静止物のピクセルが変化しないことを確認(静止物の画素はカメラ移動量ぶん平行移動するだけのはず)。
- **fps表示**:HUDにfpsとフレーム時間。
