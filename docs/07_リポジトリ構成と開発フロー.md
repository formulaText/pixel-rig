# リポジトリ構成と開発フロー

TypeScript＋Vite＋npmを採用。依頼者はiPhone SafariでCodexとGitHubを利用する。ローカルPCのセットアップは要求しない。
GitHubの公開リポジトリでコード管理し、配信もGitHub内で完結させる。GitHub Actions＋GitHub Pagesは具体的な運用案。外部ホスティングは使わない。

## 実装順

r128で分割・v5再現 → Three.js更新 → 描画基盤の拡張。各段階を混ぜない。
原本はprototypes/、現在の説明はdocs/、作業指示はdocs/issues/に分離する。実装開始後のsrc等の構成案は [12](12_v6実装計画.md) を参照。
現在のパッケージにはViteアプリや配信workflowは入っていない。

## 開発単位

1 Issue＝1 PR。実機確認は節目ごと。内部整理も検査結果をPRへ記録し、未確認の実機項目を完了扱いにしない。
各Issueの状態は未着手／実装中／比較可能／実機確認待ち／採用・完了／保留などで区別する。研究実装の完成だけで最終方式の採用を意味しない。
