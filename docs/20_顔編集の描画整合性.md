# 顔編集の描画整合性修正

2026-11-08 JST。工程2 Issue #15／PR #16内の不具合修正。工程1 PR #14への依存関係を維持する。確認済み版 `gh-42431015275-1-cd919b341526` は保持し、修正版は実機確認前にマージ・昇格しない。

## 報告と再現

依頼者の添付2画像を確認。各画像の左がドット、右が3Dで、髪非表示。キャンバスの目の絵柄が同じまま、閉じ目方式／顔全体の横位置／縦位置を操作するとプレビューの目が小さくなる。これは見た目の好みの調整ではなく整合性の不具合。

修正前 `5ca3a37` で、自動まばたきOFF、開いた目固定、静止、正面、同時刻、同じ頭、髪非表示の実UI操作を個別に再現。3操作×2表示の6ケースすべて、元絵柄・目の設定・編集キャンバスは不変、描画画像は変化し、値を戻しても元画像に戻らなかった。

## 確定した原因

`face-ui.ts` の `mutate()`／`changed()` が編集時に `face.legacy=false` を強制していた。初期状態の元の顔は投影アンカーに2×3ドットの絵柄を合成するが、falseになると `face-render.ts` の頭表面マテリアルへ切り替わる。頭相対の領域32×24内の4×6セルは画面の2×3ドットと同じ寸法を意味しないため、縮小・投影短縮・照明色の差が発生した。フラグは値を戻してもtrueへ復帰せず、編集履歴に依存していた。

閉じ目方式は開いた目の縮小率を変えていなかった。顔画像は頭メッシュの色として適用しているため、別の顔メッシュが頭に埋まることが今回の再現原因ではない。元データの劣化や二重倍率も、この6ケースでは検出していない。

以前の19で「編集すると頭表面へ切り替わる」と仕様として説明していた挙動は、本報告により不具合として撤回する。説明表示だけでは編集の整合性を満たしていなかった。

## 修正

- 描画方式を編集操作で変更しない。`legacy` は履歴フラグではなく、プリセット／保存設定が持つ元のドット配置方式の識別として維持する。
- 「現在の顔」は元の投影アンカー・サイズを使う編集用合成を提供する。元絵柄と配置範囲からキャッシュしたパーツ画像を参照する。未変更の目は既存グリフ（横向き・半目・閉じ目も含む）をそのまま使用し、初期値を保つ。設定だけが変わる場合も形・サイズを保ち、明示的なサイズ編集だけがサイズを変える。
- 顔の横／縦位置は頭ローカル座標のアンカー移動として投影し、絵柄や配置範囲のサイズを変更しない。整数格子の丸めにより小さな移動は同じ画素位置に留まることがある。
- 頭表面プリセットと旧保存データの方式は保持。目を大きくする補正値、ぼかし、時間平均、強制前面表示は追加しない。共有色バッファで深度解決済みの肌画素にだけ編集ドットを合成し、髪・背景が手前なら描かない。
- schema 3へ更新し、1／2は元の値・絵柄・方式を保持して移行する。旧版で頭表面へ切り替わった設定を勝手に元方式へ戻さない。現在の顔から確認し直す場合は「顔・頭を初期値へ」を使用する。保存済み項目を消さない。
- アトラスは設定・口・表情が変わる時だけ更新。まばたきは3状態の参照を切り替える。追加の描画パスや通常readPixelsを導入しない。Bの格子・深度精度・共有深度と通常ゲーム描画は維持。

## 検査と区別

`tests/browser/look-face-consistency.mjs` が実UIから、端末縦横×3D／ドットの開いた目、閉じ目方式の往復、横縦位置の往復、異なる操作順、基準／調整中、保存→再読み込み→復元、コピー→復元の描画画像を比較する。自動まばたきの開目・半目・閉目を同tickで比較し、停止中と再生中も往復する。

位置の移動先によって目の一部が頭の肌の外へ出る場合は、描画矩形の幅高さが一定であることを検査し、表示された目の画素数を移動先の肌マスクと照合する。自然な遮蔽による画素数減少と、今回の方式切替による縮小を同一視しない。

[操作前後の描画比較](validation/face-edit-comparison.png)は、左から旧版初期／旧版閉じ目方式変更後／修正版初期／修正版変更後。上が最終ドット、下が3D。描画元の出力をnearest拡大したもの。依頼者の画像を加工したものではない。

閉じ目方式だけを変更した再現条件では、旧版は最終ドット10画素／3D166画素が変化し、方式を元へ戻しても同じ差分が残った。修正版は変更時・復帰時とも0画素。横／縦位置0.01の再現では旧版は同じ描画方式切替が発生し、修正版は格子の丸め範囲内なので0画素。別途±0.06で実際に位置が動く条件も検査し、位置反映を無効化して差分0にしたのではない。[描画元の差分数](validation/face-edit-pixel-differences.json)。

最終検査集計は [再現記録](validation/face-edit-reproduction.json) と [修正後の描画比較](validation/face-edit-consistency.json)。公開ソースとCI・成果物照合はPR #16の最新配信記録を参照する。iPhoneの修正版は未確認で、全条件のちらつき完全消失を意味しない。既存10条件の残差と別件の原因未確定まばたき変化は引き続き04／16で追跡する。
