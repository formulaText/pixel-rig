# V6-03 検証・性能測定の基盤

対象：[Issue #8](https://github.com/formulaText/pixel-rig/issues/8)。対象ビルドのiPhone実機確認・V6-03採用・PR #9マージ・同一成果物の昇格承認を受領済み（実機結果は末尾）。実行結果はIssue #8とPR #9で記録する。PNG保存の保留、移動中の色のちらつきの原因未確定・未解決は維持する。

## 操作

パネル先頭の「検証」を開く。静止・横移動・縦移動・斜め移動・壁際・木の重なりから選ぶと、時刻0で停止する。「再生」「リセット」「1コマ進む」「結果コピー」を同じ場所に置く。検証中の通常設定は無効化し、「通常操作へ戻る」で解除する。横向きの狭い画面では検証を開いている間だけ左右配置にする。

「seed・入力列・時刻・測定条件」からseed、入力列、固定時刻を変更できる。描画設定（解像度・倍率・昼夕夜・影・顔・変換・模様・自動瞬き）は通常操作で選んでから検証へ入る。リセットはその設定を復元する。seedと入力列の編集はリセットで反映する。プリセット変更は対応する入力列を選んでリセットする。

入力は `{seconds, x, y}` のJSON配列。xは右正、yは下正、値は−1〜1。方向を正規化して既存移動処理へ渡す。各区間の秒数を既存STEPに丸めて繰り返す。画面のドラッグ入力や自動巡回は検証中の入力列に混入しない。リセットしない再生の周回では衝突で初期位置へ戻らない場合もあるため、比較は必ずリセット起点で行う。

## 時刻と乱数

- ロジックは既存の `STEP=1/60` を維持し、検証の時刻・入力列は整数更新番号から求める。描画はRAFのまま。描画頻度を30/60/120Hz相当に変えても同じ入力と更新番号を再現する。時間更新方式の本格変更はV6-07の範囲。
- 停止時はロジックを進めず、瞬き・感情・歩行・アイドル・葉・既存の水面模様が停止する。シェーダーの共有時刻も同じシミュレーション時刻。新しい水・粒子の実装はない。
- 「1コマ進む」は描画フレーム数ではなく、既存STEPの1回のロジック更新。「時刻を固定」は0から同じ入力列を再生し、指定秒を最寄りのSTEPへ丸めて停止する（最大600秒）。
- world生成と瞬き・自動感情の乱数は別ストリーム。指定seedで両方を初期化する。通常操作は原本と同じworld seed=11とMath.randomを使用する。通常の衝突判定関数・照明関数・GLSLを変更しない。
- seed変更でworldを再生成するときは古いGPU形状・マップテクスチャをdisposeし、衝突データと街灯を再構築する。通常操作へ戻るとseed11のworldに戻す。

## 性能測定

「性能測定」は現在の検証条件をリセットして入力再生を開始し、比較更新OFF・最終画面・画像読出しなしで実行する。初期選択は準備5秒＋測定10秒の短時間観察。準備30秒＋測定60秒も選べる。これらは操作用の測定枠であり、採用済みの合格閾値ではない。60fps合格判定は自動化せず、継続・熱条件・実機での評価は別に扱う。

実測した描画数、ロジック更新数、実測秒数、描画fps、RAF間隔の平均・中央値・p95・最大・50ms超回数、CPU側の更新と描画命令発行時間を保存する。50msは集計用の分類で、合否判定幅ではない。CPU値はGPU完了時間ではなく、GPU時間はnull／未取得のまま。準備期間と最初の基準フレームは集計から除く。外部録画の検出はできないため申告欄を記録する。

画像比較・PNG・バッファ切替・設定変更を測定に混ぜない。向き／内部解像度／DPR変更、非表示、フォーカス離脱、利用者停止、リセット、通常操作復帰で測定を中断し、部分結果と理由を残す。検証を閉じても再生が残る場合は「通常操作へ戻る」で明示解除できる。

結果はビルドID・元コミット・設定・seed・プリセット・入力列・初期と終了状態・画面条件・ブラウザ・測定条件をJSONに含む。画像比較と性能結果は別欄。結果コピーに失敗しても、画面内の選択可能な結果欄を残す。

## 静止領域の画素比較

「比較基準」→進行→「画素比較」。いずれも一時停止する。画像読出しはこの明示操作のときだけ。PNG保存の代用や修正ではない。

各時点で同一カメラから次の4枚を一時render targetへ描き、読出し後に破棄する。

1. 全体。
2. キャラ・顔スタンプ・感情アイコンを除く。
3. さらにキャラの足元影を除く。
4. さらに既存シェーダーの時刻を0へ固定する（葉と既存水面模様）。

隣接する画像間で変わった画素数を、キャラ・動く足元影・意図的アニメーションの影響として別記する。静止比較は4枚目同士の全共通領域であり、変化した画素を理由にマスクを作らない。建物・木のシャドウマップと現在のキャラ足元に基づく深度規則は保持し、その変化も隠さない。分離用描画の結果であり、全体画像の全画素を「問題なし」と分類するものではない。

カメラとキャラの既存の共通整数座標からスクロール量を求め、RGBAを完全一致で比較する。非共通視野と、輪郭処理が視野外を参照する両画像の外周1pxだけを除き、除外理由・数・比較数・変化数・最大差・差分例を記録する。解像度・設定・seed・入力列変更時は基準取り直し。比較領域なしは成功扱いしない。建物影や深度規則の影響などが見つかっても原因を断定せず、受入条件を自動合格にしない。

バッファ表示は既存の色・法線分類・加工済み描画深度・影をGPU上で表示する土台。readPixelsを使わない。生成していないバッファは黒表示とし、説明を添える。本来の3D深度、固有物体ID、新G-buffer、GPU時間測定を実装したとは扱わない。

## 自動検査と結果

検査結果は下記と[機械可読記録](validation/V6-03.json)に保存した。`tests/validation.test.mjs` は乱数、30/60/120Hz相当の再生、停止／1回更新／リセット、時間指定入力、縦横スクロール補正と人為差分検出、測定集計・中断を検査する。`tests/browser/validation.mjs` は実際のアプリの再生状態・画像・GPU資源・readPixels呼出し・コピー失敗からの復帰を検査する。自動検査用フックはVite検証サーバーへ注入し、配信成果物に含めない。

原本との同条件比較は引き続き `tests/browser/compare-v5.mjs`。V6-03で比較読出しの初期状態だけをOFFにしたため、原本比較ではアプリ側の比較を明示ONに揃える。それ以外の描画条件・受入幅は変更しない。

## 依頼者の短い実機確認

1. 「検証」で同じプリセットを2回「リセット」→「再生」する。
2. 「停止」と「1コマ進む」を試す。
3. 縦横は端末の向きです。端末を縦持ち・横持ちにし、それぞれ「性能測定」を押して、準備5秒＋測定10秒の自動終了まで待つ。「測定完了」の表示後に「結果コピー」を試す。
4. 「通常操作へ戻る」を押し、ドラッグで移動できることを確認する。

技術的な再現性・厳密な画素一致はCodexの検査対象。依頼者に目視での完全一致判定や既存全項目の再確認を要求しない。対象ビルドの実機確認・採用承認後、Codexがマージと同一成果物の昇格を代行する。V6-04以降はこの依頼に含めない。
